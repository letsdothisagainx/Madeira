# Madeira delivery requirements

The user develops and tests on an iPhone without a computer. For requested
development/build handoffs, complete the established GitHub Actions IPA build
and publish a downloadable IPA before ending the task. Do not replace that
deliverable with a report or withhold it because gameplay acceptance remains
unverified. If an actual build or delivery failure blocks publication, identify
the exact failure and continue working to resolve it.

Verify the package's source/component provenance and the unauthenticated public
download. Preserve the existing bundle identifier, installation, Wine prefix,
game files, Steam session, JIT setup and user configuration.

State build/test results separately from on-device gameplay results. An
installable candidate must not be described as a confirmed gameplay repair
without evidence. Follow the user's foreground-work and normal-input-only
validation constraints when present.
