## Established source defect and production correction

Published Apple XNU, inspected at commit `f6217f891ac0bb64f3d375211650a4c1ff8ca1ea`:

* [`vm_map_msync`](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/osfmk/vm/vm_map.c): KILLPAGES can be skipped for object-sharing conditions; when accepted it calls object deactivation.
* [`deactivate_pages_in_object`](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/osfmk/vm/vm_object.c): dirty/modified-state clearing and compressor-state disposal are guarded by `(flags & DEACTIVATE_KILL) && object->internal`. External pages can instead have references cleared and be moved toward inactive/pageout queues.
* [`msync` syscall handling](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/kern_mman.c) connects the public flag to VM synchronization. A successful syscall is not a dirty-disposal, completed-writeback, zeroing or offset-reuse receipt. This published tree is not a claim to have the device's exact private kernel or stacks.

`virtual_ios.c` previously ran MS_KILLPAGES on dead external backing before release, before fresh-offset decommit and before synchronous in-place punching. It also made successful discard a prerequisite for the fresh mapping, based on its incorrect no-writeback guarantee. The correction removes those external scans/deactivation calls and that gate. Fresh replacement still uses only unused or successfully punched zero offsets, only for dead complete host pages. It preserves surrounding live subpages, guest protection aggregation, content-preserving copyback, reservation accounting, the global file cap, and the offset quarantine. Old offsets return to the free list **only after actual successful F_PUNCHHOLE**; failure remains quarantined. No anonymous exception, live migration, speculative reclamation, instruction/recovery change or pool resize is introduced.

This removes demonstrated unsupported release/decommit work and its false predicate. Induced pager/writeback pressure is plausible, but the captured data does **not** establish that these retirement calls caused the dominant live aligned-store stall. The unresolved distinction is exact-page soft-fault/reference/dirty behavior of the live external mapping versus other kernel work. This candidate is not a proven remote-gameplay repair.

## Export corrections

* The synchronous `ios_swap_give` fallback now goes through the existing timed punch path. Queue entries retain retired extent generation. Slow/error and in-flight records retain file-open lifetime, offset, extent generation where known, deferred/synchronous execution and VM-lock scope. Per-operation count/bytes/errors/duration aggregates are separate from the combined counters; nested elapsed durations are not CPU. Fast paths remain try-only fixed records without allocation, formatting, filesystem logging or blocking metadata queries inside VM locks.
* After the existing target resume and VM try-lock release, up to two `mach_vm_page_query` metadata calls observe the actual host page(s) containing the sampled access. Page disposition/reference counts, status, timestamp, duration, capture separation, epochs, allocation classification and app-scoped backing-open identity remain separate from region data. Failure is unavailable, never a clean-page zero. Creation/sampling owners are not migration permission. No guest data is read or warmed, and no protection or eligibility is changed.
* Stable configuration/module/graphics summaries are written only when changed. Automatic coverage/termination checkpoints occur every five ticks and on lifecycle/export boundaries; journals still record throughout. Only dirty journals need fsync. Recorder logical bytes, checkpoints, flush/fsync work, rotation and incident copies are measured separately from host-app rusage; filesystem metadata/export copies and an unflushed tail remain explicit gaps. Received typed system summaries use the same accounting.
* Loopback activation is a phase in the existing attempt. Original explicit close reason and repeat count remain separate from FULL-signon cleanup. CPU summaries select wholly contained capture intervals against calibrated original console boundaries, excluding boundary/background overlaps; they do not use the latest parser phase as capture truth. Foreground gaps exclude prior background time and remain labelled whole-app, not remote FPS.
* Closed error schemas cover allocation, invalid arguments, missing material/resource, shader and pipeline messages and known Metal domains at existing log sites, with available numeric parameters and last-memory-sample reference. Unknown resource identity/parameters and observer coverage remain explicit; no raw chat/credential disclosure is added. Report metadata includes stable file identity and modification time, with old/new uncertainty; no dump payload is read. Startup now retains the immediately preceding session even when an older session has an incident file, using a private 36-byte session pointer (write acknowledged, not fsynced) to preserve order across wall-clock changes and a timestamp fallback when unavailable; a metadata fixture reproduces that selection case. Current live exports and preceding incomplete sessions are labelled separately, without inferring a crash from missing clean exit.

The Export Run button and streaming/cancellable one-ZIP sharing flow remain. Journals still rotate within 8.5 MiB, incident <=3 MiB, system <=1 MiB and bounded metadata, under 16 MiB/run with current/prior namespaces separate. Native ring 393,216 bytes, in-flight 4,608 bytes, per-operation aggregates 1,024 bytes; queue extent identities add 8 KiB. The 192-row CPU history and Foundation/allocator/query cost are bounded inputs, but actual iPhone physical/CPU overhead is unmeasured; the <1 MiB recording-payload goal is not a physical-footprint guarantee. Symbols remain a separate matching artifact.
