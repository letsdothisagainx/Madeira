## Implemented recording corrections

* The previous main/store observation gate stopped after 1200 samples. Structured main and watched-worker records now remain rate-limited to one per second throughout an accepted lifetime; the existing text-output cap remains in place; bounded rolling storage limits retention instead of ending observation during a later match.
* Existing main captures publish a fixed record after the matching resume. A subsequent VM try-lock copies current view/extent metadata, allocation and extent generation, recorded allocation owner, all guest subpage flags, and a conservative VM mutation epoch. One bounded Mach region query runs with no VM lock or target suspension held. Busy, unknown owner lease, changed epoch, unavailable submap and failed queries remain explicit. Register and query timestamps are distinct. No payload reads, new suspension or page warming are added.
* Existing map, guest protection/commit, host protection, decommit, discard and hole-punch paths publish bounded in-flight metadata and aggregate counts. Only slow (>=5 ms)/error completions enter the native ring. Producers make one diagnostic-lock attempt; no formatting, allocation or filesystem work occurs inside VM critical sections. Results/errno and mapping behavior are preserved.
* A passive, validated-CS2-owner DXMT pacing-hook counter makes a gap observable before 64 more frames finish. It is **not** a GPU-completion or presented-frame count. The existing detailed Present/GPU logs remain authoritative for those measurements. A gap can also be a pause; foreground state is recorded and intentional pause remains unknown.
* Export Run snapshots the automatic recorder on its utility queue, then streams immutable private files into the existing ZIP/share flow. Typed identifiers bypass neither credentials filtering nor the general text sanitizer: closed field/value schemas are encoded anew. Ancillary logs cannot consume structured evidence space first.

## Entries and limits

`evidence/run-summary.json`, `timeline.jsonl`, `thread-frame-memory.jsonl`, `memory-access.jsonl`, `vm-operations.jsonl`, `graphics-errors.jsonl`, `graphics-summary.json`, `runtime-config.json`, `modules.json`, `termination.json`, an optional pinned `incident.jsonl`, and an optional delivered `system.json` accompany existing sanitized logs. The immediately preceding sanitized native log is also retained with an explicitly unverified match to any older pinned incident; it is never assigned current counters. The previous run has a distinct `evidence/previous/<UUID>/` namespace and is never merged with current counters.

Each app session gets a UUID. CS2 lifetime identity uses validated owner/PID/lease/native thread identity, not hardcoded TIDs. Console attempts get local attempt IDs and observed remote/loopback classification; a console message isn't a team-picker/gameplay assertion or packet-arrival timestamp. Wall/monotonic calibration is repeated at lifecycle changes and periodically. Original console time and parser reception time stay separate. Module load generations/ranges and available package component hashes are retained; absent module hashes, unloaded-state tracking, connection packet timestamps and per-command GPU sequences are explicitly unavailable, not synthesized.

The native ring payload is 393216 bytes plus 3584 bytes of in-flight metadata. Generation tracking additionally expands the existing 16384-entry extent ledger by 128 KiB and each live view by 16 bytes; these are metadata, not guest physical residency. Swift drains 24576-byte batches; input/copy buffers are bounded, per-row serialization is capped at 16 KiB, inventories at 256 entries and graphics signatures at 64. The target is <1 MiB of additional retained recording payload; Foundation/allocator/MetricKit object overhead and iPhone physical overhead are not measured. The recorder emits its elapsed utility-queue time and overruns. No hard overhead guarantee is claimed.

Disk per retained run: 34 rolling 256 KiB segments (8.5 MiB), latest pinned incident <=3 MiB, received typed system summary <=1 MiB, capped metadata files <=1.25 MiB: <16 MiB. At most current and previous run directories remain. Export copies are temporary and removed by the existing sharing lifecycle. Write-acknowledged and last fsynced sequence/time are distinct; fsync runs on the utility queue every five ticks and at export, never a guest critical path. An unclean/incomplete fixture has termination reason **unknown**, not crash/jetsam. The final native ring/unread file tail may be lost on termination.

MetricKit is an ordinary subscriber, not a Mach/crash interceptor. Only actually delivered, bounded typed crash/hang/CPU/disk/memory summaries are retained; delivery may describe an earlier build/run. UUID/time matching remains uncertain where typed fields don't expose an image identity. Export never waits for delivery. Full unbounded system JSON/call-stack trees, guest minidump payloads, arbitrary Analytics/Jetsam files and kernel stacks are not collected. App-owned Wine report metadata is retained at a bounded known report root.

Matching native dSYMs and sorted symbols are a separate `Madeira-native-symbols` Actions artifact; package metadata identifies the Actions run and FEX/Wine/DXMT revisions. The IPA packaging check verifies linked native producers, Swift schema, component/provenance metadata and bundle identity.

## Verification boundary

Ordinary C/Swift metadata fixtures cover rotation, try-lock contention, in-flight visibility, sequence order, errno, typed nulls, clocks, privacy, deduplication, previous incomplete recording and disk bounds. Existing actual ZIP writer/collector/share-state fixtures cover cancellation and the one-ZIP flow. No deliberate fault/crash/protected-page experiments or execution of captured instruction bytes are used. CI compiles actual iOS Swift/Mach consumers and checks the packaged components. Device-only validation remains remote Mirage loading, CPU split and live backing correlation, responsive team selection, a sustained round, clean map/menu transition and visual correctness.
