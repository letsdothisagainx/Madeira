# CS2 game-server UDP compatibility, November 12

## Device evidence

The `58749aef` export contains a genuine earlier remote Source 2 handshake:
S2C_CHALLENGE, C2S_CONNECT, S2C_CONNECTION and Connected, followed by a player
count of 20. That connection uses Steam/SDR identity and exchanges packets.
After server changelevel it closes, and a new direct UDP connection times out
with reason 5003. The user confirms this was official matchmaking.

At local 00:09:38 the native log records `fd=1795 errno=65`, followed immediately
by the guest send error 317. On Darwin, 65 is EHOSTUNREACH. The same observation
repeats on the next send. The old native logger then exhausts its global budget.
It runs after WARN, so the new correction captures errno earlier than that log.
The final NTSTATUS and guest socket error were not recorded independently.

Expected conversion is EHOSTUNREACH -> STATUS_HOST_UNREACHABLE (c000023d) ->
WSAEHOSTUNREACH (10065). The installed Kernelbase message table lacks 10065.
FormatMessage therefore fails with 317; current public GNS reads the socket
error again after formatting it. Error 317 is not evidence of a native UDP
error with that number.

`UDP invalid@...` describes the not-yet-accepted remote identity, not an invalid
IP address. Public GNS uses this state while awaiting its handshake. Its current
Windows send code calls WSASendMsg even though its error label says WSASendTo;
this is not independent disassembly of the shipped closed CS2 library.

The accidental VAC marker is excluded. This run is not proof of final
VAC-secured match acceptance. Prior self-write corrections succeed on the
phone; JIT preparation is 5,584 ms and the 768/384 MiB partition remains intact.

## Production corrections

1. Stage the real native `try_send` implementation to snapshot errno immediately
   after a failed sendmsg. Retry decisions, NTSTATUS conversion and existing
   observers use the saved value. Observers cannot replace it with ENOTCONN or
   accidentally change the retry policy. No failed send is reported successful.
2. Reject unspecified datagram destinations with STATUS_INVALID_ADDRESS, which
   maps to Winsock 10049. This matches actual native Windows for IPv4 zero,
   IPv6 zero and IPv4-mapped zero. Never redirect these packets to loopback.
   Valid destinations, ports, payloads and flags retain their normal behavior.
3. Compile standard Winsock messages 10051, 10060 and 10065 into actual
   Kernelbase resources for ARM64, ARM64EC and I386. FormatMessage's real failure
   semantics are unchanged. Source transactions restore the pinned Wine inputs,
   and the final package checker reads each compiled PE message table.

Failure-only socket context records family, destination/bind classes, scope,
interface binding and captured status. It excludes IP addresses and payloads,
has fixed per-process/per-descriptor budgets and does not read SO_ERROR:
SO_ERROR would consume a pending error and could change transport behavior.
There are no route, VPN, JIT, Steam authentication or game-file changes.

## Actual reference results

[Native reference run 43161709483](https://github.com/letsdothisagainx/Madeira/actions/runs/43161709483)
passed on native Windows x86, Windows x64 and Darwin. IPv4 loopback, IPv6
loopback and mapped dual-stack cases exchange real nonce packets and replies.
Windows WSASendMsg and WSASendTo reject all three unspecified forms with
10049 and zero bytes; Darwin returns EHOSTUNREACH. Linux instead sends those
forms to loopback, so Linux alone is an incorrect Windows reference here.
Zero sockaddr length bytes work on Darwin for valid destinations; XNU copies
the actual length from msg_namelen. No sin_len workaround is justified.

The production regression executes the actual address conversion, native send
and status functions. It reproduces observer-induced error corruption before
the patch, checks the corrected statuses and uses real UDP payloads/replies.
It also verifies no syscall or fake completion for invalid destinations,
nonblocking backpressure, connected sockets and the existing refusal retry.

## Remaining limitation

The exported destination is irreversibly redacted. No evidence establishes
that this phone request used an unspecified address. Its family, scope, route
and interface binding are unknown. These corrections therefore do not prove
the intended game server is reachable or that reason 5003 is resolved.
If the target is valid and its route is unavailable, the corrected API must
continue returning the genuine failure. The bounded context distinguishes
that case without collecting authentication or packet data.

The current WSASendMsg implementation also omits ancillary controls. Public
GNS uses optional ECN; dropping ECN alone does not explain a kernel host-route
failure, so no speculative ECN or routing fallback is included.

Install the IPA over the existing app using the same iPhone signing identity
and bundle identifier. No prefix or data migration is required. Rollback is an
over-install of the previous IPA; do not uninstall or clear the app's data.
Actual game-server sends, responses, handshake, sustained connection and match
loading remain iPhone acceptance tests. No new FPS or memory result is claimed.
